## 3. 承認タスク（Approval Tasks）

- **一括承認／一括却下**
  - 複数ドキュメントを選択してまとめて処理
  - 大量タスク前提の運用向け

- **高度な通知・リマインド**
  - 期限が近い／遅延している承認タスクのリマインド通知
  - 承認遅延時のマネージャー／上位者へのエスカレーション通知
  - 通知頻度・タイミングの設定（例：毎朝まとめ通知 など）

- **休暇モードと代理承認（Vacation Mode）**
  - バックアップ承認者（Backup Approver）の設定
  - 代理ユーザー（Substitute User）への権限委譲

- **モバイル・外部ツールからの承認**
  - メール内リンクからブラウザ承認
  - Slack連携等を通じた承認（API連携の実装）

## 4. 発注書（Purchase Orders）

- **送料・手数料行の追加（Shipping Lines）**
  - 送料・手数料を行として追加し、原価と分離して管理

- **Excelファイルから明細一括インポート**
  - Excelテンプレートから明細をまとめて取り込み
  - Apache POI等を用いた一括処理の実装

- **変更時の自動再承認**
  - 金額・条件変更時の自動的な再承認トリガー

- **サプライヤー送付の高度管理**
  - 送信履歴・配信ステータス（未送信／送信済／開封／失敗 等）の活用

- **発注ステータス管理の自動化**
  - 紐付く受入・請求書による自動ステータス更新

- **変更履歴・リビジョンの記録**
  - POの変更履歴をリビジョンとして記録・比較

- **前払い・支払条件**
  - 前払金（Prepayment）の登録
  - 支払条件（支払サイト）の設定
  - 前払金と請求書のマッチング

- **サービスオーダー（Service Orders：中規模版）**
  - PR から Service Order を直接生成（複数PRから1件のService Orderを作成するケースも想定）
  - 過去の Service Order をコピーして新規作成（Repeat Service Order）
  - 年額契約・保守契約・SaaS など、期間ものサービスを対象とした発注書として利用
  - 1件の Service Order から複数の請求書（Invoice）を起票し、分割請求・分割支払に対応
  - サービス品目ごとに「受入なし（SO–Invoice の2点照合）」か  
    「検収書あり（SO–Receipt–Invoice の3点照合）」かを設定で切り替え可能
  - Ordered／Partially Invoiced／Fully Invoiced／Completed など、サービス向けのステータスで管理
  - POと同様に変更履歴・リビジョンを保持し、金額・期間変更時の再承認ルールと連動

## 5. 受入・検収（Receipts / Item Delivery）

- **受入の承認ワークフロー**
  - 受入に対する承認プロセス（検収印機能）

- **複数POを選択して一括レシート作成**
  - 複数POをまとめて受入処理

- **POとのマッチング・ステータス連動**
  - POとの数量・金額マッチング
  - 受入状況に応じたPOステータス更新

- **サービスオーダーとの連携**
  - サービス品目で「3点照合（SO–Receipt–Invoice）」を選択している場合は、  
    Service Order を起点にサービス検収用の受入ドキュメントを作成
  - 2点照合設定のサービス品目は受入ドキュメントを作成せず、  
    Invoice と Service Order の突合のみを行う

## 6. 請求書（Invoices）

- **3点照合（3-way Match）**
  - PO・Receipt・Invoiceの3点突合ロジックの実装
  - 数量・金額の許容誤差（Tolerance）設定
  - Service Order の 2点/3点設定に応じて、照合パターンを切り替え

- **承認ワークフロー**
  - 請求書の承認プロセスを定義

- **繰り返し請求書（Recurring Invoices）**
  - 定期的な請求書の自動生成

- **一括支払処理**

- **支払検索・レポーティング**

## 10. 予算管理（Budgets）

- **予算（親）の作成・設定**

- **予算レポート・通知**
  - 予算超過や消化率に基づくアラート通知
